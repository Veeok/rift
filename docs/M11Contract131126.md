# M11 Rift Inspection Foundation

Status: implementing; not complete. Scope: backend inspection through existing MCP/shared-service/reader entry points. No dashboard rewrite, mutation tools, hooks, dependency installation, configuration/model changes or publication.

## Architecture and reference

Dex reference: https://github.com/LorekeeperZinnia/Dex (Explorer hierarchy, stable selection, property inspector, duplicate-name identity). Dex's README warns about duplicate instances/deferred events. Adapt these inspection ideas, not its executor mutation features or UI. Reuse Rift's exact segment references, tagged Roblox values, registry, protected reads, bounded traversal, decompile jobs/cache, source index and MCP structuredContent support.

Use reader-native operations rather than repeated host calls or arbitrary Luau execution. Keep current tools compatible; add `get_subtree`, `inspect_instances`, `discover_source`, `get_source_excerpt`, and extend `search_instances` filters. No silent source decompilation. New reader capability: `inspection_v1`; unsupported older readers return an actionable error, never fabricated results.

## Shared interfaces, revision 1

- Instance references remain `{id?:string,path?:string[]}`; paths are exact segments, not dotted selectors. Explicit IDs win. New APIs reject ambiguous name paths instead of choosing an arbitrary duplicate. Detached/streamed/destroyed objects produce per-item failures when possible. Reconnect invalidates references/cursors.
- Results retain existing top-level payload fields and raw text blocks. `structuredContent` exposes a decoded object with `metadata` plus original payload aliases. Complete source uses a distinct `sourceText:string`, pending/error source uses null. Source never gets folded into metadata or a generic JSON string. Errors keep `isError`; typed image blocks are untouched.
- `inspectionSchema` exported by `src/inspection.ts`: `{get_subtree,inspect_instances,search_instances}` maps each name to a Zod raw input shape. `registerInspectionTools(server,bridge)` registers ONLY the two new operations. Lead merges `inspectionSchema.search_instances` into existing search input and removes its old name/class-only precondition. Worker must export a reader capability check/helper as needed and document usage.
- `get_subtree`: target optional root; requested `properties` <=32; maxDepth 0..16 default2; maxVisited 1..10000 default1000; maxNodes 1..200 default50; offset 0..10000 default0; maxProperties 1..32 default8; maxResponseChars 2048..100000 default40000. Flat items contain object identity, parent ID, depth, selected tagged properties and per-object errors. Include root. BFS pagination is explicitly a re-observation, not a stable snapshot; report visited/returned, nextOffset/hasMore, partial/partialReason and limitsReached/omissions. Depth, queue, property count, traversal/deadline and final response size must all be bounded.
- `inspect_instances`: targets 1..50 explicit refs; same requested-property/value/output limits; preserve input index/ref and each success/error. One bad reference must not discard good items. Reject invalid argument shapes before reader traversal; retain stale-ref errors per item.
- Search additions: `ancestor?:Ref`, `attributes?:[{name,op,value?}]`, `tags?:{all?:string[],any?:string[],none?:string[]}`, `propertyFilters?:[{name,op,value?}]`, `guiText?:{value,match?,caseSensitive?}`, `visible?:boolean`. All filter categories and predicates are AND; tags.any is OR within its list. Comparisons: eq/ne on same-type finite scalar string/boolean/number, contains/prefix only strings, gt/gte/lt/lte only finite numbers, exists boolean. No Lua patterns or coercion. Property names use a documented safe allowlist; unsupported names/combinations are rejected before traversal. Ancestor means strict descendant (not the ancestor itself). `visible` means effective GUI enablement: own/ancestor GuiObject.Visible and LayerCollector.Enabled; not viewport occlusion or clickability. Non-GUI objects do not match either visibility value. Bound ancestors scanned to64, report unknown/unreadable visibility as omissions rather than inventing a match. Empty richer-filter-only query is valid; totally empty search remains invalid.
- `toolResult(metadata:Record<string,unknown>, options?:{sourceText?:string,isError?:boolean,content?:CallToolResult['content']}):CallToolResult` in new `src/tool-result.ts`; response worker also adapts `read-script-result.ts` without breaking existing CM tests. Lead applies to existing core/shared results and catches. Must not stringify/relabel typed media or silently truncate inside arbitrary objects. Worker supplies bounded-result helpers if necessary, with exact documented behavior.
- `SourceDiscovery` in new `src/source-discovery.ts`: constructor accepts `{bridge,decompiler,getProvidedSources:()=>SourceRecord[],readScript:(args:Record<string,unknown>)=>Promise<CallToolResult>}`; `discover(args)` and `excerpt(args)` return payloads (not MCP envelopes). `sourceDiscoverySchema` exports raw Zod shapes for `discover_source` and `get_source_excerpt`. Lead registers them only in shared service and wraps payloads through toolResult. Inventory comes from existing list_scripts; cache stays DecompileService. Current session and connection must be captured/rechecked after awaits. Fail safely on reconnect.
- Discovery metadata filters: nameContains/pathContains/className/loaded/running plus optional literal cached-source query. Limit inventory pages (default2,max10), metadata revalidation(default10,max50), results(default20,max100) and response chars(default40000,max100000). Default refresh false. Report scope/completeness, enumerated/known eligible, cached, missing, stale and unverified counts (no unknown scripts represented as observed missing). Path-filter counts must not reuse unfiltered totals. Include provided_execution as a separately identified scope. Revision is SHA-256 of exact available source; bytecode hash separately named, never confused with source revision.
- Excerpt: one explicit script, optional expectedRevision, startLine default1/maxLines default30<=200/contextLines<=20/maxChars<=20000. Cached-only by default. `fetchMissing:true` explicitly authorizes only this one script via existing read_script handler/jobs; preserve pending state/job ID without re-executing decompile. Excerpt payload `{metadata,sourceText}`; metadata has identity/revision/observation, start/end/total lines, cursor and truncation reasons. Revision mismatch is explicit. Preserve redaction before clipping and accurate line numbers. Never require/execute inspected scripts.
